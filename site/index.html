原则

设计原则

声明式烧录计划

一份 JSON 描述一个 ECU：段（内联 / BIN / Intel HEX / S-record）、会话、安全访问、擦写校验例程、时序、恢复策略、电源守卫、期望指纹、身份期望——可版本化、可评审、可复用。ODX/PDX 子集导入与计划 lint（段重叠、空洞、缺数据）在任何驱动调用之前拦住坏计划。

三道门禁，先验证后动手

身份门先读 expectedIdentity DID——目标不对、DID 不支持、载荷不足，都在任何会话变更之前中止并留下有界证据；指纹门把镜像钉死在计划里，指纹不对在任何驱动调用之前拒绝；复位后确认门轮询 DID，直到 ECU 证明它回来了——卡死的 ECU 拿不到绿灯。

电源守卫：真表才测量

powerGuard 是强制执行的条款：接入电表 provider——CI 与台架用确定性仿真 provider，真机接外部 vendor 脚本实时输出 mA，厂商代码留在引擎之外——擦除与每个下载块期间轮询电流，越界即永久中止：物理安全事件绝不盲目重试。没有 provider 的计划不假装测量。

失败即证据

--report 把每次刷写写成 flashpilot.report/v1 证据工件：UTC 起始、传输、带耗时的审计步骤、身份/指纹门记录与结局；失败的尝试落同一份报告。错误文本有界，恢复策略 retry / resetAndRetry 强制执行，擦除与下载永不盲目重试——断电重跑从指纹门重新开始。

退出码永不撒谎

0 成功 · 1 刷写/断言失败 · 2 用法错误 · 3 未找到 · 4 传输错误；每条命令打印一个 JSON 对象——camelCase、字段名稳定、错误文本有界，不用抓屏去猜。

Agent 界面：CLI 与 MCP

无常驻进程 CLI 之外，同一引擎讲 stdio MCP：flashpilot_validate / flashpilot_flash / flashpilot_request / flashpilot_udid / flashpilot_odx_import 五个 agent 工具，CI 冒烟测试守住接口面——agent 用母语跑完整条烧录链。

证据

支持边界，按证据说话

支持矩阵的权威载体是代码：flashpilot transports --json 输出每个传输/适配器子集的证据级别；文档与 CLI 输出由测试锁死，不会漂移。

hardware-in-loop verified

存在版本化适配器 + 参考 ECU 复现报告（issue #4 门禁）；宣称仅限该适配器/ECU 类别，绝不外推到任意 ECU。

ci-simulated

完整闭环（会话 → 安全访问 → 擦除 → 下载 → 校验 → 复位）在每次推送的 CI 中对仿真 ECU 运行。

implemented-unverified

代码随源发布并尽可能单测；尚无实体适配器 + 参考 ECU 的复现报告。

planned

明示未实现，避免猜测。

上手

三步开始

装上引擎

从 Releases 下载对应平台的 CLI zip（免装 Racket），或从源码一行装好引擎与 CLI。

git clone https://github.com/turlamai/flashpilot.git
cd flashpilot
raco pkg install --auto --name flashpilot --link racket

仿真 ECU 空跑闭环

默认传输是内置模拟 ECU：会话 → 安全访问 → 擦除 → 下载 → 校验 → 复位的完整闭环走真实实现的 ISO-TP/UDS 协议栈，全程免硬件，CI 每次推送复跑。证据级别 ci-simulated——仿真闭环验证的是编排与协议，不是真机刷写结果。

racket app/cli.rkt flash examples/plan.sim.json

指向真实 ECU（先看证据等级）

DoIP 是当前唯一 hardware-in-loop verified 的传输；SocketCAN（Linux）与 PEAK PCAN（Windows）为 implemented-unverified——上真机前，把适配器、固件与 ECU 和资格记录对齐。

racket app/cli.rkt flash plan.doip.json --transport doip --host 192.168.0.1

01

先阅读手册，选择随库提供的模拟器和示例计划。

02

先在不接触真实设备的情况下验证计划，检查确定性输出、失败状态和日志。

03

使用真实硬件前，将适配器、固件、ECU 与具体资格记录匹配，并建立恢复与断电处理流程。
